# 软件麦克风隐私：安全基础

日期：2026-10-05。第一版已接入服务 API、串行保存线程、物理麦克风键与
应用采集链。显式 `--privacy --state-dir` 才提供持久软件隐私。
服务不打开 PCM，也不绑定语音平台。

## 已实现

- `src/privacy.h` 的 `PrivacyState`：初始静音；无有效持久记录时保持静音。
  静音请求立即使运行状态为 muted；解除请求也先保持静音，只有对应代次的
  持久保存成功才能解除。失败、目录同步不确定、过期或重复完成不能解除。
- `PrivacyGate`：应用自己的录音许可与全局状态分别判断。未取得有效快照、
  隐私能力不可用、非法隐私数据或连接丢失均不允许采集；重连快照清除旧许可，
  应用须重新核对自己的许可。解除全局静音不自动启动任何应用。
- `src/privacy_store.h` 的 `PrivacyStore`：已有私有目录、独占 `privacy.lock`，
  同 UID、文件私有权限、单硬链接及非符号链接检查。状态严格为
  `{"version":1,"muted":true}` 或 false；损坏/缺失读取返回失败并把输出置为 true，
  不自动写默认记录。临时文件写入、文件 fsync、原子 rename、目录 fsync；
  失败清理临时文件，不无限重试。锁与音量锁分开，可以放在同一私有目录。

`--state-dir` 单独启用只保存音量；另加 `--privacy` 才保存隐私。
未启用标志的 mock 保留内存模拟，controls 不报告真实隐私能力。

## 调用与线程约束

`PrivacyState` 与 `PrivacyGate` 均由各自单线程使用。`PrivacyStore.load/save`
是同步 I/O 原语：在启动初始化/独立持久化线程调用，不能塞入 socket
事件循环；没有 hard real-time fsync 保证。

接入顺序：服务主线程 request 获得 `{generation, muted}` → 保存线程串行保存
目标状态 → 主线程 complete。保存线程不能并行写同一状态文件；旧请求完成
被运行状态忽略，不意味着旧请求可以晚于新请求覆盖磁盘。限频/合并必须保留
这个顺序约束，不直接复用音量的两秒延迟机制。

客户端应先订阅，再取最新状态并按有序事件更新；由传输层校验版本、事件顺序
及队列溢出。每次失联/协议失败调用 `lost()`，停止 KWS、采集和网络上行，不能
自动回退到直接录音。普通空闲轮询超时不等于连接断开。重新确认应用许可后
调用 `consent()`；`allowed()` 只是许可判断，不会自行启动/停止工作线程。

ApplicationClient 在失联、协议失败、请求超时和队列溢出后清除许可。
迁移应用在读取 PCM 前后检查，静音停止 KWS，失联停止采集/上行。
实机验证正在采集时断开服务，两类应用均关闭 PCM；不强制约束未知程序。

## 断电与故障边界

成功保存表示文件及目录 fsync 均返回成功，实际 NAND/文件系统及断电行为还
需要设备验收。目录 fsync 失败时 rename 可能已可见，但不算持久成功。

若磁盘旧记录是 false，新的静音保存失败或尚未完成就断电，重启可能读到旧
false；不能声称“运行中静音成功”就保证了下次启动静音。运行中仍保持 true，
必须报告保存失败/待完成。新应用启动/重连仍不得继承旧的录音许可。

即使文件损坏时默认静音，也无法仅靠这个文件检测“完整且合法的旧 false”是
否过期。若要求失败静音跨断电也绝对不可撤销，需要额外的启动默认静音策略
或可靠持久介质/事务方案，不能靠重试或 UI 文案掩盖这个限制。

软件隐私不是物理断电，也不能约束绕过接口、直接打开 ALSA 的其他进程。

## 验证记录

`make test` 加入独立 `privacy-test`，覆盖默认/损坏静音、延迟解除、旧完成竞态、
断线/重连许可、文件重载、锁竞争、严格 schema、权限、symlink、FIFO 和
file/directory fsync 故障。23 项原有服务回归及新单元测试通过；新测试通过
ASan/UBSan 和 AArch64/musl SDK 编译。此段是基础组件验证，不代表完整实机验收。

第一版已完成以下接入：

1. 接入有界串行保存线程与 mock API，补 privacy.changed/persistence 事件及
   结构化日志：加载失败、立即静音、待保存、保存失败/恢复、真正解除。
2. 物理全局按键只执行一次；安全指示不能被普通灯租约覆盖。
3. 客户端与实际采集链接入失联保护，逐一验证停止采集/KWS/上行。
4. 状态写入当前 overlay，重启服务核对；实际断电/满盘故障和长稳尚待验收。
