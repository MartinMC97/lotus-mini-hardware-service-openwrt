# P2 控制后端与接入门禁

当前后端组件已接入 daemon 的显式 `--controls --handoff-confirmed` 模式，
**尚未部署或完成实机控制验收**。
`--mock` 仍只维护模拟状态，`--read-only` 仍拒绝控制；不能据此认为实机灯和
按键已经由硬件服务接管。没有新增远程接口，也没有部署或停止现有应用。

## 灯

`src/controls.h` 的纯时间函数计算 RGB 占空比，支持关闭、常亮、单色呼吸、
双色往返渐变和总亮度。采用余弦平滑周期，主题色和待机调度由应用提供。

`src/led_backend.h` 的 LedRunner 只用一个输出线程，100 Hz 软件 PWM，按变化
边沿输出而非忙等。取消代次和互斥锁保证 set(off) 返回后没有旧动画边沿重新
点亮；析构最后尝试关闭。输出失败停止动画，healthy=false；恢复需要显式 set，
没有自动重试/抢回硬件。SysfsRgb 的固定 profile 使用三路 brightness 的 0/1。
硬件断开时关闭只能尽力而为，不能保证不可写的灯实际熄灭。

构造 SysfsRgb 不打开节点；调用 write 才写入。LedRunner 析构会写 off，所以
真实 sink 的创建与销毁也必须放在交接范围内，不可在旧控制者运行时“试着创建”。
控制模式已挂到 socket，启动/失败/恢复记录日志并报告能力降级。

## 按键

EvdevButtons 根据 EVIOCGNAME 和键能力匹配 gpio-keys/adc-keys，不依赖 event
编号。固定 profile：播放 164、麦克风 248、音量减 114、音量加 115；同身份
重复设备视为歧义并拒绝发现。一个匹配设备可部分可用，仍需后续能力分别报告。
不使用 EVIOCGRAB；不能靠它阻止旧应用重复执行动作，启用前必须停旧处理者。

每轮每设备最多读 64 条非阻塞事件。重复值 2、未知键码、重复边沿不产生动作。
手势阈值暂定：30 ms 防抖、300 ms 双击窗口、800 ms 长按；短按为避免与双击
重复，延迟到双击窗口结束才发出。音量键需要 P3 专门的立即步进策略，不能把
这套延迟手势直接用作最终音量体验。SYN_DROPPED/读失败取消待处理手势，不
伪造松开或重复动作；丢失同步后要有完整的新按下/松开才能重新识别。

这些阈值尚未经实机体验验收。已实现播放键到 owner 的专用动作路由，其他
订阅者仅观察；没有自动重新发现、全局音量/静音动作或强应用安全隔离。
输入设备须支持 EVIOCSCLOCKID，统一单调时间用于屏蔽交接前的缓冲按键。

## 验证与下一步

`make test` 包含独立 controls-test 与现有 17 项 socket 集成测试。controls-test
使用 fake sink 和显式时间，验证全白、呼吸端点、渐变中点、50 次切换取消、
输出失败、短/双/长按、重复、防抖、输入状态重置及缺节点。模拟不能验证 GPIO
调度抖动、实际 evdev ioctl/热插拔或物理按键。ASan/UBSan 和 AArch64/musl
交叉编译用于补充检查，不代表实机控制已通过。

2026-10-05 已接入上述受限控制模式；新增两项 socket fixture 测试覆盖控制
交接标志、缺节点/恢复、白色三路输出、租约竞争、渐变取消、断线关闭、过期
关闭及退出关闭。fixture 是临时常规文件，不是 GPIO 或真实 evdev。
真实输入事件路由还没有端到端实机验收，不将纯手势测试冒充该项完成。
